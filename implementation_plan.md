# Vector: AI Decision Intelligence & Assurance Platform for Autonomous Infrastructure

Vector is a trust validation layer designed to fit between observability metrics and automated infrastructure remediation. Instead of blindly executing playbooks, Vector analyzes, simulates, and verifies the safety of proposed actions. 

This implementation plan outlines the MVP architecture, highlighting a pluggable infrastructure layer, and a phase-by-phase build strategy.

---

## User Review Required

We propose a **modular monolithic architecture** for the MVP to ensure high velocity and simple local deployments during the hackathon, built with strict abstractions for pluggability.

> [!IMPORTANT]
> **Pluggable Infrastructure Adapter Layer (Mandatory)**: 
> To support starting with simulated telemetry/state and plugging in real infrastructure later, we will implement a strict interface contract (Adapter Pattern):
> - **`KubernetesAdapter` Interface**: Defines operations like `scale_deployment`, `restart_pod`, and `get_workloads`. We will implement a `MockKubernetesAdapter` (default) and a `LiveKubernetesAdapter` (using the official Python `kubernetes` client) that can be toggled via environment variables.
> - **`MetricsAdapter` Interface**: Defines operations like `get_current_metrics` and `get_historical_metrics`. We will implement a `MockMetricsAdapter` (driven by the simulator) and a `LivePrometheusAdapter` (querying a Prometheus HTTP API).
> 
> **Database Choice**: For portability, we recommend starting with **SQLite** (using SQLAlchemy) which requires zero local setup. We can easily transition to **PostgreSQL** in production or later phases since SQLAlchemy abstracts the database dialect.

## Verification Plan

### Automated Tests
We will write unit tests using `pytest` for the backend:
- Test telemetry generation values and trend limits
- Test prediction engine calculations (linear extrapolation)
- Test decision scoring weights and output bounds
- Test policy verification pass/fail gates
- Test `MockKubernetesAdapter` vs `LiveKubernetesAdapter` schema validation to ensure both satisfy `BaseKubernetesAdapter` interface contract.

```bash
pytest backend/tests/
```

### Manual Verification
1. **Scenario CPU Spike**:
   - Go to Simulator Page, trigger a `CPU Spike` on `payment-service` with `High` severity.
   - Go to Dashboard, verify CPU chart spikes, and warning banner appears.
   - Go to Decision Center, verify candidate actions scale, inspect Decision Score, verify "Auto Execute" triggers (or requests manual approval if policies restrict it).
   - Verify cluster returns to normal telemetry (recovery).
   - Go to Timeline, inspect full chronological flow of the CPU Spike incident.
2. **Policy Enforcement Verification**:
   - Change `Database Restart` policy to **Require Manual Approval**.
   - Trigger `Memory Leak` incident on a database workload.
   - Verify the action pauses at `Awaiting Human Approval` in the UI and presents "Approve" / "Reject" buttons.
   - Click "Approve", verify execution begins and metrics recover.
